# Privacy, Sandboxing & Operational Safety

This document details how **`02`** isolates runtime artifacts, protects personal credentials and local environment metadata, and enforces safe hardware and web automation boundaries.

---

## 1. Two-Layer `.gitignore` Isolation

Runtime execution generates sensitive and bulky local artifacts inside `<project_root>/.02/`:
- **`.02/browser_profile/`** — Persistent Chromium cookies, session tokens, IndexedDB, and cache.
- **`.02/logs/`** — Local execution traces and URL/screenshot captures.
- **`.02/resources/`** — Shallow-cloned external GitHub repositories.
- **`.02/state.json`** — Machine-local RAM/GPU telemetry snapshots and task state.

To guarantee these never reach source control:
1. **Repository Root `.gitignore`** ignores `.02/`, `.env`, `.env.*`, `*.pem`, `*.key`, `secrets.*`, `credentials.*`, `__pycache__/`, and local IDE folders.
2. **Sandbox-Local `.02/.gitignore`** (auto-generated by `bootstrap.py`) independently ignores `browser_profile/`, `logs/`, and `*.tmp` even if a target project adds `.02/state.json` to custom tracking.

---

## 2. Zero-Credential & Zero-PII Repository Policy

Before publishing or syncing changes to GitHub, verify every file in the repository against these rules:

- **No Secrets or `.env` Files:** Never commit `.env`, API keys or personal access tokens, OAuth secrets, or private certificates.
- **No Local Machine Usernames or Absolute User Paths:** Never hardcode OS user-home directory paths or personal workspace folders inside `SKILL.md`, scripts, or documentation. Use `$env:USERPROFILE`, `$PSScriptRoot`, `Path(...).resolve()`, or `<02_SKILL_DIR>` placeholders instead.
- **Privacy-Safe Git Commit Identity:** On machines where global `~/.gitconfig` stores a personal name or email address, configure repository-local commit metadata using your GitHub noreply email before committing:
  ```powershell
  git config user.name "<your-display-name-or-handle>"
  git config user.email "<id>+<username>@users.noreply.github.com"
  ```
- **Automated Secret & Path Audit:** The test suite in `tests/test_02_suite.py` includes automated checks verifying that tracked source and documentation files do not contain common API token patterns, `.env` files, or Windows user-home path literals.

---

## 3. Dependency & License Sandboxing

`scripts/scavenger.py` prevents supply-chain clutter and commercial licensing accidents:
- All external clones are pinned strictly inside `<project_root>/.02/resources/`.
- Shallow clones (`--depth 1`) reduce disk footprint and download bandwidth.
- Every cloned repo's `LICENSE*` header is checked against `FREE_LICENSES`, rejecting proprietary or subscription-gated code before integration.

---

## 4. Responsible Web Automation Boundaries

`scripts/stealth_browser.py` is designed for legitimate user-authorized workflows (testing web apps, inspecting JS-rendered UIs, preserving authenticated session state, and fetching public documentation):
- Never commit or share `.02/browser_profile/`.
- Do not use automation scripts to bypass CAPTCHAs, violate target site terms of service, perform unauthorized scraping, or execute high-rate denial-of-service traffic.
- Keep concurrent browser contexts at or below the `hardware_policy.md` cap (`2` simultaneous contexts).
